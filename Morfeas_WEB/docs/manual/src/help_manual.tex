\section{Introduction}
LOG WEB is the browser user interface for daily operation and configuration of the LOG system.
This manual describes the current \textbf{new} LOG WEB interface and is intended for operators and service users.

\subsection{Naming Note}
LOG WEB is the current product and user-interface name. \textbf{Morfeas WEB} is the legacy name.
Some internal paths, service names, repository names, protocol identifiers, and code comments may still use \texttt{Morfeas}, \texttt{Morfeas\_WEB}, or related forms for code compatibility and to avoid breaking existing deployments.
Operator-facing UI and current user documentation should use \textbf{LOG WEB}, except where an exact technical identifier must be shown.

Unless a site-specific deployment says otherwise, open the system in a browser with:

\begin{itemize}
\item \texttt{http://<device-ip>/}
\end{itemize}

This manual does not describe the retired legacy Morfeas WEB layout.

\section{Main Page}
The landing page is \textbf{ISO Channels Linker}. It is the main operational screen.

\subsection{What You See}
The page contains:

\begin{itemize}
\item a top bar with the FTP backup directory chip and rolling system summary,
\item a search bar,
\item action buttons for importing and adding channels,
\item the main ISO channel table,
\item a right-click context menu for channel actions,
\item a menu button that opens all secondary pages.
\end{itemize}

\subsection{Main Table}
The table shows the configured ISO channels and related runtime information.
Typical columns include:

\begin{itemize}
\item status,
\item ISO channel name,
\item device type,
\item connection anchor,
\item current value,
\item history,
\item next calibration,
\item minimum and maximum values,
\item description.
\end{itemize}

The page refreshes automatically while it is visible, so operators normally do not need to reload manually.

\subsection{Next Calibration}
The \textbf{Next Calibration} column is calculated from calibration metadata stored with each ISO channel.

\begin{itemize}
\item For \textbf{SDAQ} channels, calibration date and period come from the SDAQ runtime calibration data when the device reports it.
\item For \textbf{IOBOX}, \textbf{MTI}, and \textbf{NOX} channels, calibration metadata is stored in the OPC UA channel configuration as \texttt{CAL\_DATE} and \texttt{CAL\_PERIOD}.
\item When a non-SDAQ channel is added and no other calibration metadata is entered, the Add Channel popup defaults \texttt{CAL\_DATE} to the current date and \texttt{CAL\_PERIOD} to 12 months.
\item The displayed next calibration date is \texttt{CAL\_DATE + CAL\_PERIOD} months.
\item A missing or invalid calibration date or period is shown as \texttt{---}.
\end{itemize}

For example, a non-SDAQ channel added on \texttt{2026-05-11} with the default 12-month period is shown with next calibration \texttt{2027-05-11}.

\subsection{Measurement Display Rules}
The \textbf{Value} column follows the runtime measurement semantics of the current system.

\begin{itemize}
\item Normal valid measurements are shown as numeric values with the unit when a unit is available.
\item \textbf{Out of Range} and \textbf{Over Range} continue to show the actual runtime measurement value. They are not converted to an error code.
\item Reserved runtime error codes are shown as \textbf{red integers} in the \textbf{Value} column.
\item Reserved error codes are shown without units and without decimal formatting.
\item Reserved error codes are not collapsed to \texttt{---}.
\end{itemize}

\textbf{MTI Disabled note:} Disabled is an operator-selected radio mode, not a measurement fault. If MTI telemetry is disabled, the web shows \textbf{Status = Disabled} and leaves \textbf{Value} as \texttt{---} unless LOG core explicitly provides a numeric channel value. This keeps OPC UA/logstat measurement values owned by core and prevents the web interface from inventing error codes.

\textbf{NOX mapped-channel note:} NOX uses dynamic sensor nodes for UniNOx addresses. If the NOX handler is not running, the bus has been switched away from NOX, or a sensor address has never been detected, the web linker table may show \textbf{Status = OFF-Line} with \textbf{Value = ---} because no logstat runtime source exists. The OPC UA mapped \textbf{Value} may return \texttt{-905} for the same ISO link because the mapped source node is missing. These two displays describe the same missing-source condition from different layers.

LOG core treats a detected NOX sensor as active through exactly 10 seconds since its last message. At 11 seconds it is offline. While a sensor is present but reports a heater-off, heating, or invalid condition, core publishes the corresponding reserved value instead of passing through a stale NOx or O2 measurement.

\subsection{Reading Status Together with Value}
Operators should read the \textbf{Status} and \textbf{Value} columns together:

\begin{itemize}
\item \textbf{Status = Out of Range} or \textbf{Over Range} with a numeric \textbf{Value} means the device still reports a measurement, but the channel is flagged as outside the expected calibrated or device range.
\item \textbf{Status = No sensor}, \textbf{OFF-Line}, \textbf{Disconnected}, \textbf{Stall}, or \textbf{Unclassified} together with a red negative \textbf{Value} means the measurement is not valid and the code should be interpreted using the error-code table above.
\item \textbf{Status = Unconfigured} with \textbf{Value = ---} means the device is reachable, but the configured runtime channel path is not present.
\item \textbf{Status = Disabled} with \textbf{Value = ---} means the function is intentionally turned off, not failed.
\end{itemize}

\subsection{Search}
Use \textbf{Search Input} to filter channels in the current table.

\subsection{Add Channel Device Search}
The Add Channel popup uses device search to choose runtime source paths for new links.
Search results are limited to the selected device family and to paths that are not already linked in the current OPC UA channel configuration.

\begin{itemize}
\item \textbf{SDAQ}: search lists real channels from detected, registration-complete SDAQ devices that are not already linked. The saved identity is the canonical \texttt{serial.CHn}; the current CAN bus/address is display-only and is never saved as channel identity. A real device channel may be linked even when it currently reports \textbf{No sensor}.
\item \textbf{IOBOX}: search lists channels from IOBOX devices whose runtime connection status is \textbf{Okay}. A receiver marked \textbf{Disconnected} is not listed. Individual channels under an online receiver may still be listed even when their current status is \textbf{No sensor} or otherwise invalid, matching the current channel-selection contract. Each IOBOX receiver also exposes \texttt{RXn.Status} and \texttt{RXn.Success} link metrics. \texttt{RXn.Status} reports \texttt{1} when the receiver link is okay and \texttt{0} when it is not okay, with no unit. \texttt{RXn.Success} reports the receiver packet success ratio from \texttt{0} to \texttt{100\%}. If the IOBOX device itself is unreachable after an ISO channel has already been linked, these mapped values follow the normal missing-source error path and may report \texttt{-905}.
\item \textbf{MTI}: search lists channels only when the MTI runtime connection status is \textbf{Okay} and the radio/telemetry mode provides channel data. Modes \textbf{TC4}, \textbf{TC8}, \textbf{TC16}, and \textbf{QUAD} expose their channel list. \textbf{RMSW/MUX} exposes detected \textbf{Mini\_RMSW} measurement channels. \textbf{Disabled} does not expose Add Channel candidates.
\item \textbf{NOX}: search lists \textbf{NOx} and \textbf{O2} entries for detected UniNOx sensor objects. The current measurement does not need to be valid; for example, heater-off, warming-up, or previously detected \textbf{OFF-Line} sensors may still be linked and controlled later. OFF-Line historical candidates are marked with \texttt{(OFF-Line)} in the search result.
\end{itemize}

The search popup and save validation both enforce device-family matching. IOBOX candidates are not accepted as MTI links, and MTI candidates are not accepted as IOBOX links, even if the physical equipment connected behind the device can be similar.

Typing in the Path field only searches the current candidate list. A typed value must resolve to an available candidate before Save; it is not a Manual or offline channel-entry path. SDAQ Unit is read-only and comes from live device metadata, so Add does not store an SDAQ Unit in the OPC UA XML configuration.

\subsection{Add Channel ISO and Multilinking Rules}
With \textbf{Range = 1}, the entered ISO code may be saved even when it is not present in the selected ISOstandard.

With \textbf{Range greater than 1}, every generated base ISO code must exist in the selected ISOstandard and remain in the same measurement category. The numeric suffix is expanded without adding an extra leading zero; for example, \texttt{TEMP099} continues as \texttt{TEMP100}.

A selected cylinder postfix is applied only after the batch ISO sequence is validated. For example, the ISOstandard lookup uses \texttt{TEMP1}, \texttt{TEMP2}, and \texttt{TEMP3}, while cylinder 5 is saved as \texttt{TEMP1\_5}, \texttt{TEMP2\_5}, and \texttt{TEMP3\_5}.

The multilinking naming and rejection rules follow \emph{Rules for how to name channels in Laboratory measurement systems}, Document ID \texttt{DMTA00018532}.

Range Add is one all-or-nothing operation. LOG WEB rechecks every selected channel immediately before writing; if any source, ISO name, or identity conflicts, no channel in the range is written.

\section{SDAQ Link and Gateway Mapping}
Adding a channel in LOG WEB and mapping it in the Lab OPC UA Gateway Configuration Tool are separate operations. LOG WEB creates the link; the Gateway discovers it during browse and stores its own metadata snapshot when the point is configured and saved.

\subsection{Online Add and First Mapping}
For a new point:

\begin{enumerate}
\item In LOG WEB, confirm the SDAQ channel is online and that Unit, device Type, CAN location, and calibration information are correct.
\item Add the channel from the current Unlinked search results.
\item In the Gateway Configuration Tool, perform a complete browse or rebrowse of the LOG endpoint.
\item Confirm the Lab OPC UA Gateway mapper shows the expected Unit, Type, Address, and SDAQnet values.
\item Configure and save the point.
\end{enumerate}

\subsection{Device Goes Offline Before First Mapping}
The XML link and ISO object remain, but Current Core hides the required Unit browse reference while current runtime metadata is incomplete. A fresh Gateway browse therefore should not offer the point for first mapping.

Do not force \textbf{Configured} or save empty or uncertain metadata. Reconnect the device, wait for registration and metadata to complete, confirm the values in LOG WEB, and then perform a complete rebrowse before the first Configure/Save.

\subsection{Restored Historical Channel Is Currently Offline}
Local JSON or FTP Restore may restore a valid canonical \texttt{serial.CHn} identity while that SDAQ is offline. This preserves the link so the same serial and channel can recover automatically if it later appears on this LOG; it does not prove that the device is currently detected, and it does not configure the Gateway.

Before the device is ready, a fresh Gateway browse should not map the point. After the same serial/channel is online and its metadata is correct, perform a complete rebrowse and, if the point has never been configured on this endpoint, configure and save it. A serial that never appears on this LOG remains offline and is never silently moved to another address or device.

\subsection{Previously Mapped Device Goes Offline}
Do not delete an existing saved Gateway point merely because a fresh browse temporarily shows it as missing or not mappable. The Gateway keeps its saved metadata and Value NodeId. Value may become \texttt{-905} and status may show offline/unregistered; when the same \texttt{serial.CHn} returns to the same LOG, Value recovers without remapping.

If the SDAQ is moved to another LOG, the old LOG mapping remains offline. Add the device from the new LOG's Unlinked list and perform first mapping against the new LOG endpoint.

\subsection{Browse Cache, No Sensor, and Unclassified Unit}
The Core browse gate affects new browse results; it cannot clear a point tree already cached by the Gateway Configuration Tool. A device can go offline after browse but before Save, so confirm that it is still online and perform the tool's complete browse/rebrowse operation immediately before first Configure/Save. A normal page refresh is not guaranteed to clear the Gateway's internal browse cache.

The Gateway does not automatically discover a new ISO object and does not automatically refresh metadata it has already saved. After a sensor or Unit changes, rebrowse, verify the metadata, and save again.

\textbf{No sensor} means the physical SDAQ channel exists but has no sensor connected; it may be linked and typically reports \texttt{-902}. \textbf{Unclassified} Unit means Core received a unit code it cannot classify; it is not an empty string, but it is not confirmed engineering metadata. Link success does not mean a point is ready for first Gateway mapping. Connect the actual sensor and confirm Unit, Type, Address, SDAQnet, and calibration before first mapping. If \texttt{Unclassified} was already saved in Gateway metadata, later sensor recovery does not rewrite it automatically; rebrowse and save again.

\section{Add Devices}
Open \textbf{Add Devices} to manage the current device inventory.

\subsection{Page Layout}
The page has three main areas.

\begin{itemize}
\item \textbf{CAN Bus Setup}: shows each CAN bus, current mode, bitrate, state, detected device count, and available actions.
\item \textbf{Configured Devices}: shows XML-backed devices that can be removed or configured.
\item \textbf{Detected Devices}: shows auto-detected runtime devices, especially SDAQ devices found from logstat data.
\end{itemize}

The page refreshes while the popup is focused. Polling pauses during remove or role-change operations so the displayed state does not fight the operation in progress.

\subsection{SDAQ Operation Flow}
\begin{itemize}
\item SDAQ devices are auto-discovered from runtime \texttt{logstat} data.
\item They appear in \textbf{Detected Devices}; they are not manually added with the \textbf{Add...} form.
\item To use a CAN bus for SDAQ, use the \textbf{Switch to SDAQ} action in \textbf{CAN Bus Setup}. The system sets the SDAQ role and expected bitrate, restarts the LOG service, then waits for SDAQ runtime data to appear.
\item After SDAQ devices are detected, link individual SDAQ channels from the main page with \textbf{Add Channels}.
\item If a bus is in SDAQ mode but no SDAQ appears, check wiring, power, and CAN bitrate/state in the same table.
\end{itemize}

LOG core remembers the address associated with an SDAQ serial number for 14 days after the device goes offline. A returning device normally recovers that address. ISO channel identity is still the canonical \texttt{serial.CHn}; the remembered CAN address is only an advisory runtime reservation and is not the saved channel identity. After an on-card software upgrade from the older address-cache format, the cache is rebuilt from devices currently online, so addresses may be reassigned without changing canonical channel identity.

\subsection{NOX Operation Flow}
\begin{itemize}
\item NOX is managed by CAN bus role, not by the manual \textbf{Add...} form.
\item Use \textbf{Switch to NOX} on the target CAN bus to assign that bus to NOX operation. The transition changes the role/bitrate together and restarts the LOG service.
\item When a bus is in NOX mode, \textbf{Open NOX Config} opens the NOX configuration page for that bus.
\item Use the NOX configuration page for sensor setup and NOX-specific live controls.
\item To remove NOX from a bus, use \textbf{Switch to SDAQ}. When removing a configured NOX row, the UI may also ask whether to restore the bus to SDAQ.
\end{itemize}

\subsection{IOBOX Operation Flow}
\begin{enumerate}
\item Click \textbf{Add...}.
\item Select \textbf{IO-BOX}.
\item Enter \textbf{Device Name}, for example \texttt{IOBOX\_01}.
\item Enter the IOBOX IPv4 address.
\item Click \textbf{Save}.
\item Confirm the service restart warning.
\item Wait for the page to refresh and show the configured device runtime status.
\end{enumerate}

Behind the UI, saving an IOBOX writes the device into the LOG configuration XML and restarts the LOG service. Duplicate device names and duplicate IPv4 addresses are blocked.

\subsection{MTI Operation Flow}
\begin{enumerate}
\item Click \textbf{Add...}.
\item Select \textbf{MTI}.
\item Enter a \textbf{Device Name}; for MTI it must follow D-Bus element rules: letters, numbers, and underscore only, and it must not start with a digit.
\item Enter the MTI IPv4 address.
\item Click \textbf{Save}.
\item Confirm the service restart warning.
\item After the device is listed, use \textbf{Open MTI Config} from the configured row to manage MTI setup, telemetry mode, and MTI-specific controls.
\end{enumerate}

Behind the UI, saving an MTI writes the device into the LOG configuration XML and restarts the LOG service. The page compares configured name/IP with runtime MTI logstat data to show whether the device is connected.

\subsection{Remove Devices}
\begin{itemize}
\item Select one or more rows in \textbf{Configured Devices}.
\item Click \textbf{Remove} or press \textbf{Delete} while focus is not inside a form field.
\item Confirm the service restart warning.
\item The selected XML-backed devices are removed and the LOG service is restarted.
\end{itemize}

\subsection{Operator Notes}
\begin{itemize}
\item SDAQ rows in \textbf{Detected Devices} are auto-discovered and are not removable from this page.
\item Manual add currently supports IOBOX and MTI only. SDAQ is auto-discovered; NOX is controlled through CAN bus role switching.
\item If the page shows a legacy MDAQ warning, add/remove and CAN role actions are blocked until the legacy MDAQ XML configuration is removed manually.
\item Any add, remove, or CAN role transition may need 10--60 seconds because the LOG service restarts.
\end{itemize}

Each backup bundle contains the current OPC UA channel configuration XML and the LOG device configuration XML. The bundle is compressed, uploaded to the selected FTP engine directory, and stored as an \texttt{.mbl} file.

\subsection{Automatic Nightly Backup}
\begin{itemize}
\item The deployment installs a root cron job that runs the FTP backup script every night at \texttt{00:10}.
\item Automatic backup only runs when a valid FTP configuration exists.
\item If no FTP configuration exists, the backup script logs that no valid engine number is configured and does not change system state.
\item After a backup, the script uploads the backup logs to the same FTP engine directory when possible.
\end{itemize}

\subsection{Manual Backup}
\begin{enumerate}
\item Open \textbf{Backup \& Restore Channels}.
\item Confirm or enter the FTP server IP.
\item Enter the engine number.
\item Click \textbf{Connect \& Fetch}.
\item Wait for \textbf{Connected to FTP... Configuration saved}.
\item Click \textbf{Backup Now}.
\item Wait for the success message and confirm that the new \texttt{.mbl} file appears in the list.
\end{enumerate}

\subsection{Restore}
\begin{enumerate}
\item Connect to the FTP server and engine directory.
\item Select one backup file from the list.
\item Click \textbf{Restore Selected}.
\item Review the preflight errors and warnings. Hard errors must be corrected; warnings require explicit confirmation.
\item Confirm Restore and wait for the result message.
\item Reload the current LOG WEB and verify both channel and device configuration.
\end{enumerate}

\begin{itemize}
\item Restore downloads the selected \texttt{.mbl} file from FTP.
\item Preflight validates both configuration files against the DTD, strict channel/device rules, and IOBOX/MTI channel-to-handler relationships. A hard error prevents all writes.
\item Restore is a complete replacement of both the OPC UA channel configuration XML and the LOG device configuration XML; it is not a channel merge.
\item The two files are locked and replaced in a fixed order. This prevents ordinary Web operations from interleaving, but it is not a power-loss-atomic transaction across both files.
\item If the browser, Web process, or power is interrupted during Restore, run the same Restore again and recheck devices and channels.
\item A restored offline SDAQ follows the Gateway mapping rules in \textbf{SDAQ Link and Gateway Mapping}. Do not force first Gateway configuration while the device identity or runtime metadata is unavailable.
\item Backup files are listed newest-first, and old remote backups are pruned so the engine directory keeps up to 50 \texttt{.mbl} files.
\end{itemize}

\subsection{Operator Notes}
\begin{itemize}
\item Backup and restore both require a reachable FTP server.
\item If the server is unavailable, the page shows an error and no configuration is changed.
\item If two browser sessions edit the FTP configuration, the page detects the updated configuration and refreshes the backup list.
\end{itemize}

\section{Import Channels}
Use \textbf{Import Channels} on the main page to create channels from a JSON file.

\subsection{How Import Opens}
Clicking \textbf{Import Channels} opens the browser file picker. Select a \texttt{.json} file; there is no separate import popup page.

\subsection{Expected File Format}
The file must contain a JSON array. Each entry must include:

\begin{itemize}
\item \texttt{ISO\_CHANNEL}
\item \texttt{INTERFACE\_TYPE}
\item \texttt{ANCHOR}
\item \texttt{DESCRIPTION}
\item \texttt{MIN}
\item \texttt{MAX}
\end{itemize}

Optional fields include alarm fields, \texttt{UNIT}, \texttt{CAL\_DATE}, and \texttt{CAL\_PERIOD}. For SDAQ imports, LOG WEB ignores \texttt{UNIT}, \texttt{CAL\_DATE}, and \texttt{CAL\_PERIOD} because these values come from the live SDAQ runtime/calibration path.

\subsection{Typical Import Flow}
\begin{enumerate}
\item Prepare or export a JSON array of channel entries.
\item Click \textbf{Import Channels}.
\item Select the JSON file.
\item LOG WEB preflights every row and reports \textbf{Ready to restore}, \textbf{No change}, \textbf{Update metadata}, \textbf{Invalid}, or \textbf{Conflict}.
\item Correct every Invalid or Conflict row, then run preflight again. Core-valid orphan or device-type relationship findings are shown separately as warnings.
\item Review every warning and confirm the operation. Confirmation explicitly acknowledges the current warning list. LOG WEB re-parses and rechecks the complete candidate under the configuration lock and writes the resulting channel set once.
\item The main table refreshes after the atomic merge succeeds.
\end{enumerate}

\subsection{Validation and Conflicts}
\begin{itemize}
\item The import fails if the file is not valid JSON or is not a JSON array.
\item Local JSON Restore is an atomic channel-set merge: rows in the file are added or updated, but existing channels absent from the file are not deleted.
\item Same ISO plus the same source may update allowed metadata. Same ISO with a different source, or the same source with a different ISO, is a conflict.
\item Duplicated ISO names or source identities within the file are conflicts.
\item If any row is Invalid or Conflict, the whole import writes nothing. There is no partial-success state and no need to guess which rows were changed.
\item A warning does not make the file invalid. For example, a valid IOBOX or MTI channel may refer to a handler absent from the current device configuration. Such a channel can be restored but remains offline until the matching handler is added. Warnings must be explicitly acknowledged; a commit without acknowledgement writes nothing.
\item Commit checks that the configuration has not changed since preflight, then repeats parsing and conflict checks while holding the lock.
\item A canonical offline SDAQ row may be restored, but it is not ready for first Gateway mapping until that serial/channel is online with complete metadata.
\end{itemize}

\subsection{Export as Import Source}
The right-click \textbf{Export} action creates a JSON file in the same structure expected by import. This is the safest way to move selected channel definitions between devices, then review the file before importing it elsewhere.

\subsection{Scale}
Scale is available only for \textbf{SDAQ-I} and \textbf{SDAQ-U} rows.

\begin{enumerate}
\item Right-click an SDAQ-I or SDAQ-U row.
\item Choose \textbf{Scale}.
\item Review \textbf{Current Measurement Value}.
\item Enter \textbf{Measurement Input Low}, \textbf{Measurement Input High}, \textbf{Engineering Output Low}, \textbf{Engineering Output High}, and \textbf{Engineering Unit}.
\item Review \textbf{Scaled Output Value}.
\item Click \textbf{Save}.
\item Use \textbf{Continue in Calibration} when you want to add or review calibration points for the same channel after saving the quick scale.
\end{enumerate}

The scale popup writes a new two-point calibration table into the selected SDAQ channel calibration data. Scale is itself a calibration operation, not a display-only scaling shortcut. If the channel already has an active point table, LOG WEB shows the existing point count and requires confirmation before replacing it. The new table receives today's calibration date and a re-calibration period of zero; it never inherits the previous table's date, period, or coefficients.

\textbf{Scale is nominal range setting, not a traceable recalibration.} It applies the sensor's declared transfer function (for example, 4--20 mA to an engineering range) and does not use a reference standard. Therefore its fixed period of zero means the channel does \textbf{not} appear in the Next Calibration schedule. If the channel requires a traceable calibration interval, use the full Calibration workflow with a reference standard instead of Scale.

Scale may be performed again later. Each confirmed Save is a new calibration and replaces the previously active table with the newly entered two-point table. Save the Scale before choosing \textbf{Continue in Calibration}; that button opens the full editor for a subsequent calibration and does not transfer unsaved Scale fields.

\subsection{Calibration}
Calibration is available for SDAQ rows.

\subsubsection{Purpose}
The calibration popup is a channel calibration point editor for the selected SDAQ channel. It is used to read, inspect, preview, and save the device calibration table.

\subsubsection{Page Layout}
The popup contains:

\begin{itemize}
\item \textbf{Upper Section}: device information, calibration metadata, and summary panel share the top area.
\item \textbf{Current Preview}: \texttt{Measured raw value}, \texttt{Current Device Output}, and \texttt{Preview Output}. Each value has a copy button when the value is available.
\item \textbf{Point Table}: \texttt{Uncalibrated value}, \texttt{Reference value}, \texttt{Offset}, \texttt{Gain}, \texttt{C2}, and \texttt{C3}.
\item \textbf{Preview Columns}: \texttt{Calibrated value} and \texttt{Difference (Calibrated - Reference)}.
\item \textbf{Summary Panel}: calibration type, slope or gain summary, offset, reference minimum and maximum, and unit.
\end{itemize}

\subsubsection{Buttons and Validation}
\begin{itemize}
\item \textbf{Read from SDAQ}: reload calibration directly from the device.
\item \textbf{Discard Changes}: restore the last data loaded into the popup.
\item \textbf{Edit Calibration Points}: unlocks point editing for a channel that already has calibration data. Confirming this action converts the editable table to auto-linear points and may overwrite existing coefficients.
\item \textbf{Save to SDAQ}: validate the current auto-linear point form and write it to the device.
\item Independent date/period-only editing is not available. Calibration Date is stamped automatically with the current date when the point table changes; Re-Calibration Period is saved only as part of that same point-table calibration.
\item \textbf{CH's Unit} must be selected from the supported runtime SDAQ unit list.
\item \textbf{Used Points} must be an integer between zero and the device maximum.
\item In point editing mode, \texttt{Uncalibrated value} and \texttt{Reference value} must contain finite numbers.
\item \texttt{Uncalibrated value} (device \texttt{Measure}) must be strictly increasing by row after conversion to the device's float32 representation. LOG WEB does not reorder rows. Values that look different as decimal text but become the same float32 value are rejected.
\item \texttt{Reference value} may increase or decrease, depending on the sensor and engineering range.
\item A new zero-to-one-point calibration uses unity gain and calculates an offset. Re-saving an existing genuine linear one-point table may retain that table's gain. Reducing a multi-point or polynomial table directly to one point is rejected because no valid slope can be inferred.
\item A one-point table has no bounded calibrated interval, so the SDAQ Out-of-Calibrated-Range supervision is unavailable. LOG WEB requires a separate warning confirmation before saving one point.
\end{itemize}

\texttt{Offset}, \texttt{Gain}, \texttt{C2}, and \texttt{C3} are shown for transparency. In normal point editing mode they are read-only and LOG WEB recalculates them from the calibration points before saving. The goal of each used point is that \texttt{Difference (Calibrated - Reference)} is as close to zero as possible.

\subsubsection{After a Calibration Write}
After a successful Scale or Calibration save, use \textbf{Read from SDAQ} once and verify the active point count, point values, unit, calibration date/period, and live output before starting the formal measurement run. Normal operation does not require repeated writes, a long polling window, or a mandatory power cycle.

If the table or output is abnormal, stop using that channel, preserve the readback evidence, and power-cycle the target SDAQ itself before reassessing it. Restarting only the browser, LOG service, or \texttt{SDAQ\_worker} is not the same as removing power from the SDAQ. The recorded delayed-change event has no confirmed root cause, so LOG WEB does not add repeated writes or artificial stress operations to reproduce it.

\item Confirm that the FTP configuration belongs to the expected engine number.
\item Reload after reconnecting to the FTP server.
\end{itemize}

\item For Replace TC16, confirm that the source is a complete offline TC16 group with channels CH1 through CH16.
\item If the source group is partial, use normal single-channel replace instead.
\end{itemize}

\subsection{No Eligible TC16 Target Is Listed}
\begin{itemize}
\item No full unlinked TC16 target device is currently available.
\item If channels on the target are already linked, the target is blocked.
\item Refresh the popup after any device or link changes.
\end{itemize}

\subsection{Logs or Journal Look Empty}
\begin{itemize}
\item Use \textbf{Reload} once to refresh the selected tab.
\item Verify that the correct logger file or journal scope is selected.
\item If the service has not produced messages yet, the view may be temporarily empty.
\end{itemize}

\subsection{Red Negative Measurement Codes Are Shown}
\begin{itemize}
\item \texttt{-901} means the handler is alive, but the individual source, receiver, sensor, or channel is offline or disconnected.
\item \texttt{-902} means no sensor is present.
\item \texttt{-903} means the channel is stalled, heating, or not ready for valid measurement.
\item \texttt{-904} means the runtime data is invalid without a more specific mapping.
\item \texttt{-905} means the device-level source is unreachable or the mapped OPC UA source node is unregistered.
\item \texttt{-906} means standby / heater off.
\item \texttt{-907} means signal invalid / data invalid.
\item When these codes are shown, the measurement should not be interpreted as a physical live value.
\end{itemize}

\subsection{Restored SDAQ Point Cannot Be Mapped Yet}
Confirm that the stated serial is connected to this LOG, registration is complete, and the channel is online. Check Unit, Type, Address, SDAQnet, and calibration. When these values are ready, perform a complete Gateway rebrowse before first Configure/Save. A restored XML link by itself is not proof that the device is present.

\subsection{Previously Mapped Point Appears Missing After SDAQ Went Offline}
Do not immediately delete the saved Gateway point. First determine whether the SDAQ is temporarily offline or has moved to another LOG. A same-serial return to the same LOG restores the existing Value path; moving it to a new LOG requires Add and first mapping on the new endpoint.

\subsection{Gateway Shows the Old Unit After a Sensor Change}
Gateway metadata is a saved snapshot and is not refreshed automatically when SDAQ runtime metadata changes. Reconnect the sensor, confirm its current Unit in LOG WEB, then perform a complete Gateway rebrowse and configure/save the point again.

\subsection{Restore Was Interrupted}
Run the same FTP Restore again, then reload LOG WEB and verify both Devices and ISO Channels. Treat restored offline SDAQ channels according to the first-mapping guidance above.

FTP Restore replaces the saved XML files as a bundle and does not rewrite individual SDAQ channel fields through the Local JSON rules. A historical FTP backup may therefore still contain SDAQ \texttt{UNIT}, \texttt{CAL\_DATE}, or \texttt{CAL\_PERIOD}; current Core ignores those XML fields for SDAQ and uses live device data. Local JSON Restore instead reports those fields as ignored and removes them from the resulting SDAQ channel XML.

\subsection{Import Reports an Invalid or Conflict Row}
The entire Local JSON import was rejected and no rows were written. Correct or remove every reported row, run preflight again, and then confirm the whole merge. There is no partial result to clean up.

If preflight reports only warnings, read them before continuing. The file remains eligible to commit, but LOG WEB requires explicit confirmation. Cancelling or submitting without warning acknowledgement writes nothing.

\subsection{Scale Reports an Existing Calibration}
This is informational, not a permanent block. Scale is a new two-point calibration. Review the current active point count and the replacement warning, then confirm only if the old point table should be replaced. The new Scale receives today's date and period zero. It is a nominal range setting and will not appear in the Next Calibration schedule. Choosing \textbf{Continue in Calibration} opens the full editor for another calibration; it does not save unsaved Scale entries.

\subsection{SDAQ Calibration Readback or Output Is Abnormal}
Stop using the affected channel for measurement and preserve the table/readback evidence; do not attempt rapid repeated writes. Power-cycle only the affected SDAQ, wait for the same serial/channel to return, then read and check the table and output again. Escalate the device for investigation if the values do not recover or the condition returns.

\subsection{Channel Configuration Validation Is Unavailable}
LOG WEB deliberately refuses Add, Edit, Replace, Delete, Import, or Restore writes when the delivered \texttt{Morfeas.dtd} cannot be read. This prevents an unvalidated \texttt{OPC\_UA\_Config.xml} from replacing the working configuration. The DTD must be installed in \path{/home/morfeas/configuration/}, beside \texttt{OPC\_UA\_Config.xml}. Restore the matching product DTD and its read permissions, then retry the original operation. Do not create a blank or locally modified replacement. Existing Core channels are not deleted merely because this Web validation dependency is unavailable.
